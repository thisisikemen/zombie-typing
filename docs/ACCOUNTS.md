# 任意ログイン・個人記録の同期

更新: 2026-10-31。コード・マイグレーション・テストを実装済み。本番の入口は `VITE_ACCOUNTS_ENABLED=false`（未設定も無効）。Supabaseの個人記録用SQLは本番へ適用済み。外部認証設定と実アカウントでの端末間検証を終えてから有効にする。

## 確定した体験

- タイトルの「スタート」は従来どおり。ログイン通信を待たずにプレイできる。
- 任意の「ログイン・新規登録」からGoogleで認証する。新規登録時は、この端末・このブラウザの自己ベスト、VS自己ベスト、名前を引き継ぐ説明と確認欄を表示する。
- 別端末・別ブラウザの未登録データは自動統合しない。それぞれのブラウザに残る。登録したい記録がある端末で登録するよう案内する。
- 初めての人が「ログイン」から入っても、説明と引き継ぎ確認が済むまで空のゲーム記録を作らない。認証済みであれば、そのまま説明確認後の新規登録を完了できる。
- 初回のゲームアカウント作成時だけ記録を初期化する。すでに同じGoogleアカウントのゲームアカウントがある場合、新規登録ボタンを使ってもゲスト記録で上書きしない。
- 既存アカウントへログインしたときは、アカウントの記録を読み込む。端末のゲスト記録は別に保持する。
- 次回のアクセスではSupabase SDKが保存したセッションを復元し、有効なセッションの更新を行う。サイトデータ削除、プライベートモード、認証失効等では再ログインが必要。共有端末向けにログアウトを用意する。
- ゲーム中・リザルトで認証状態が変わっても、メニューに戻るまで記録の所有者を切り替えない。

## 保存・同期

ゲストの元のキーを残し、会員データは `zombie-typing:account:<user-id>:` 以下へ保存する。名前・自己ベスト・VS記録・既存ランキング用端末キーを会員間で共有しない。音量・BGM等は端末設定のまま。

同期は初回の読み込み、メニューへ戻ったとき、会員記録の変更後、オンライン復帰、タブが再表示されたとき、再同期ボタンで行う。同期失敗時もキャッシュを消さず、会員の自己ベストは次回まとめて送る。通常スコア・エンドレス生存時間・VS撃破数それぞれの指標で、大きい記録をサーバーに残す。表示名は未送信の変更だけを送る。

新規登録の引き継ぎ指示は、認証前にsessionStorageへ保存し、同期成功後に消す。30分の期限を設け、データが壊れていれば拒否する。認証が中断・失敗してもゲストの元データを削除しない。

ファイル書き出しは現在の保存先を対象とする。ログイン中のファイル読み込みは拒否し、別端末のゲスト記録が意図せず会員に混ざらないようにする。

## セキュリティ境界

- `player_records.user_id` をAuthユーザーに対応させ、RLSで本人だけが読めるようにする。
- ブラウザにはテーブルの直接書き込み権限を与えない。`sync_player_records` は実際の `auth.uid()` と期待するユーザーIDが一致する場合だけ実行する。トークンが別ユーザーへ切り替わった場合は拒否する。
- 初期記録のINSERTはアカウント単位で一度だけ。行ロック下で更新して、別端末の古いベストで更新しない。
- キーの許可リスト、数値、名前、VS入力時刻の配列サイズ、JSONの容量を検証する。購入権限や認証情報を同期データへ混ぜない。
- 認証コールバックのcode等を解析初期化前にURLから取り除く。セッションの保存・更新はSupabase公式SDKを使用する。
- 旧公開ランキングは端末キー方式のまま。会員ごとに新しい端末キーを使うのでゲスト・他会員の旧スコアを更新しない。ランキングのアカウント単位への統合・旧スコアの本人確認・不正スコア対策は別の作業。
- この機能の個人記録はクライアント由来で、検証済み公式スコアや購入権限を意味しない。

## 本番有効化の手順

1. 適用済み: `supabase/migrations/202610310001_optional_accounts.sql` を対象プロジェクトへ2026-10-31に適用した。既存scores等を変更しない。テーブル作成済みの状態で繰り返し実行しない。追加の `202610310002_require_registration_consent.sql` も適用済みで、初めてログインした場合の取り込み確認を必須にする。
2. Google Cloudでこのゲーム専用のOAuth設定を行う。必要なスコープは基本のopenid・email・profileのみ。Gmail・Drive等のアクセスは要求しない。有料APIや課金設定は不要。
3. ウェブアプリ用OAuthクライアントを本人が作成する。承認済みリダイレクトURIは `https://vizhznqrgasepakokygv.supabase.co/auth/v1/callback`。クライアントシークレットはGit・チャット・公開ビルドへ入れない。
4. 本人がSupabaseのGoogleプロバイダーへクライアントID・シークレットを設定する。ブラウザ操作ルールにより、新しい認証情報の作成・入力は本人に引き継ぐ。
5. Supabase Authの許可するRedirect URLに本番 `https://zombietyping.jp/?account=return` と、開発検証用 `http://127.0.0.1:5175/?account=return` を個別登録する。別のホストも公開する場合はそのURLを個別に確認する。広いワイルドカードを使わない。AuthのSite URLも本番へ設定する。
6. プライバシーページへGoogle認証の利用、保存する個人記録、アカウント削除・問い合わせ手順を追記済み。公開前に反映を確認する。アカウント削除は本人確認を行う運用を決める。
7. `VITE_ACCOUNTS_ENABLED=true` の開発版で、本人が新規登録する。端末Aのゲストベストが引き継がれ、別ブラウザBのゲストベストは自動統合されないこと、同じアカウントのベストを別端末で復元できること、再読み込みでセッションが復元されること、ログアウトで元のゲスト記録へ戻ることを確認する。本人のGoogle初回登録・再読込時のログイン復元・記録保存は確認済み。別ブラウザへの復元テストは未完了。
8. 有効化した本番ビルドをデプロイし、実際のURLで同じ項目を確認する。一般向け公開前の検証版は `VITE_ACCOUNTS_TEST_MODE=true` を併用し、Googleのテスト利用者のみ登録可能であることを表示する。

## 検証

`npm test` はPostgreSQL互換のPGliteでマイグレーションを実行し、RLS・RPC権限・初回限定の引き継ぎ・単調なベスト更新を検証する。Auth通知・セッション復元・新規登録フロー・途中でのアカウント変更は、DOMとSDKモックによるテストも行う。本番Supabaseでの検証とは区別する。

```sh
npm test
npm run build
VITE_ACCOUNTS_ENABLED=true npm run build:hosting-preview
npm audit --audit-level=high
```

公式資料: [Supabaseのセッション](https://supabase.com/docs/guides/auth/sessions)、[Googleログイン](https://supabase.com/docs/guides/auth/social-sign-in/auth-google)、[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。

## 外部設定の進捗（2026-10-31）

- 本番でRLS有効、anonのSELECT不可、authenticatedのテーブル直接書き込み不可、anonの同期RPC実行不可、authenticatedの同期RPC実行可をカタログ照会で確認。公開APIでも個人記録の読取・同期はHTTP 401 / 42501で拒否された。既存ランキングの読み取りと端末キー非公開も4項目の実API確認で維持されている。
- Google Cloudに専用プロジェクト `Zombie Typing`（`maximal-cabinet-513216-j6`）を作成済み。課金設定やAPIキー作成はしていない。本人がGoogleのユーザーデータポリシーへ同意し、OAuthの初期構成を作成済み。本人のGoogleアカウント1件をテストユーザーに登録した。ウェブ用OAuthクライアント「Zombie Typing Web」とSupabase callback URLを入力し、本人がクライアント作成とSupabaseへの設定を完了し、公開設定APIでGoogleプロバイダー有効を確認した。Google側は外部・テスト中で、Googleのブランド情報（ホームURL・プライバシーURL・承認済みドメイン zombietyping.jp）は保存済み。対象画面の「アプリを公開」が有効になったが、本人が一般登録の公開を了承し、Google側は「本番環境」へ切り替え済み。本人の実認証・初回記録保存・セッション復元は確認済み。

- SupabaseのSite URLを `https://zombietyping.jp/` に保存済み。Redirect URLsは本番 `https://zombietyping.jp/?account=return` と検証用 `http://127.0.0.1:5175/?account=return` の2件のみ。
- 独自ドメインのHTTPS 200は確認できた。旧URLの記録を新URLへファイルで移すのは任意。移さず空の記録で登録・プレイできる。本人が希望したChrome旧サイトの記録はUIから書き出し済みで、新URLへ読込・初回登録を完了。登録後にUIから書き出した6個の自己ベスト・1個のVS記録・名前の8項目が元記録と一致した。検証用localhostの記録で本番アカウントを初期化しない。

実機確認: 新ドメインと保存領域が別の localhost:5175 で既存Googleアカウントへログインし、サーバーから戻った自己ベスト6件・VS記録1件・名前の8項目が元ファイルと一致した。ローカルのゲスト記録は初期登録に使っていない。同一ブラウザ内の別オリジンでの確認であり、別の実端末での確認はまだ行っていない。

2026-10-31、本人の明示了承後にGoogleの対象を本番環境へ切り替えた。新ドメインの公開版は `VITE_ACCOUNTS_ENABLED=true`、`VITE_ACCOUNTS_TEST_MODE=false`。未ログインのままプレイできる。
