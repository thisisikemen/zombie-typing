# 事業化の初期方針

更新: 2026-10-30。まずは無料の一人プレイを育て、広告で収益を検証する。スキン販売は早くても約1か月後、リアルタイム対戦は一人プレイの完成度を見て判断する。

## 今回準備したもの

- 既存SEO・OGPを活用し、`SITE_URL` でcanonical・OGP・構造化データ・sitemap・robotsをまとめて切り替える。
- 運営情報・問い合わせ・利用案内・プライバシーのページとゲーム内リンク。
- GA4の許可設定、開始・終了・再挑戦・シェア操作の集計。未設定なら解析通信なし。
- AdSense所有確認メタタグとads.txtの生成。広告配信タグは含まない。
- CIでのテスト・ビルド・依存監査、Dependabot、環境ファイルの除外。
- ランキングの端末キーの共通フォールバックを廃止し、公開列を制限するSQLを用意。
- 独自ドメイン移行前に、自己ベスト・設定・ランキング識別情報を利用者自身で引き継げる機能を追加。

本番のDB権限修正の適用状況は [セキュリティ確認](SECURITY-REVIEW.md) に記録する。ローカル変更と本番反映は別。

## 優先順位

|順序|やること|完了の目安|
|---|---|---|
|1|ランキングの公開権限を修正|公開列の制限は本番反映済み。既に公開されたキーへの対処方針は残る|
|2|ブランド用ドメインを選ぶ|購入者・更新費・登録情報の公開範囲を確認して取得|
|3|ホスティングを確定してドメイン接続|HTTPS、検索用URL、共有画像、ランキングが動く|
|4|GA4を作成して計測を有効化|公開・アクセス受信確認済み。個別ゲームイベントの受信確認は残る（運用手順参照）|
|5|1〜2週間の一人プレイを観察|難易度別開始数・終了率・再挑戦率を記録|
|6|広告の所有確認・審査・配信|審査通過後、タイトルや結果画面の外側から小さく試す|
|7|一人プレイの改善を1件ずつ検証|改善前後で再挑戦・再訪・不具合の変化を比較|
|8|スキン販売の要否を判断|継続して遊ぶ人と欲しい見た目が見えた時点で、購入保存・復元を設計|

## 独自ドメインで正式公開済み

`zombietyping.jp` を2026-10-31に本人がXServerドメインで取得した。有効期限は2027-10-31。初年度0円、自動更新設定済みで、更新料金の案内は年3,102円。

Cloudflare Workers Static Assetsで検証用URLを公開済み。[設定値・費用・切り替え順序](CLOUDFLARE-LAUNCH.md)を参照。Cloudflareの無料DNS・Workerの独自ドメイン接続とXServerのネームサーバー変更は完了。DNS反映とHTTPSを確認し、正式公開URLを `https://zombietyping.jp/` へ切り替えた。任意のGoogle登録・個人ベスト保存も一般向けに有効化済み。旧GitHub Pagesは記録書き出し用に維持する。

## ホスティングについての重要な確認

GitHub Pages公式には、オンライン事業・eコマースや商取引を主目的とするサイト等の利用制限がある。広告つき無料ゲームの可否をここで断定しない。収益化前に用途を確認し、適合しない場合は**静的ファイルの配信先だけ**を変更する。オンライン対戦のためのバックエンド移行とは別の判断であり、Supabaseやゲームロジックを作り直す必要はない。

現在の `dist/` は静的ホスティング用。ドメイン購入を先行しても、DNS接続は配信先を確定してから行う。

## 最初に見る数字

- ページ閲覧数と流入元（GA4の標準レポート）。計測は同意した人の範囲であり総利用者数とは異なる。
- 難易度別 `game_start`、`game_end` と終了理由 `clear / gameover / quit`。
- `game_retry` と `share`（シェア画面を開いた回数。実際の投稿数ではない）。
- 日ごとの再訪状況と、広告導入後の収益・表示回数・プレイ継続への影響。

開始はカウントダウン完了時。再挑戦は再挑戦を選んだ時。ページ離脱やタブを閉じたプレイは終了イベントが届かないため、終了率は参考値とする。WPM・正確率は平均だけでなく難易度ごとに見る。

## 利用者自身が決める・操作するところ

ドメインの購入・更新契約、GA4/AdSenseのアカウント作成や規約同意・審査、受取口座や本人確認。コード・メタデータ・動作確認・移行準備はこちらで進められる。費用が発生する契約は勝手に行わない。

既存のGoogleフォームがゾンビタイピングの問い合わせを受け付けていることを確認し、主な問い合わせ先として案内した。返信先メールアドレスは任意。公開の不具合報告にはGitHub Issuesも利用できる。
