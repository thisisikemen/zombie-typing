# 確認番号メールの公開準備

2026-10-31: 本人がResend登録・専用キーのSupabase保存を完了。専用ドメイン認証と送信TLS必須、日本語テンプレートを適用済み。指定の運営者アドレスへの配信、誤った番号の拒否、本人の番号入力による既存会員ログイン、記録同期、再読み込み後のログイン保持、ログアウトを確認済み。新規の別アドレスでの実登録と実時間経過後の期限切れ確認は未実施。以下は設定の控えと再設定の手順。

## 用意した文面

Supabase Authentication → Emails → Templatesに設定する。件名は両方「ゾンビタイピングの確認番号」。

| テンプレート | 本文 |
|---|---|
| Confirm sign up | `confirm-sign-up.html` |
| Magic link or OTP | `magic-link-or-otp.html` |

`{{ .Token }}` を残す。メールには確認番号だけを表示し、リンククリックやパスワード入力を要求しない。外部の画像・解析・リンク追跡は使用しない。両テンプレートは本番適用済み。

## 送信設定（適用済み）

| 項目 | 設定 |
|---|---|
| サービス | Resend Free（有料契約しない） |
| 送信ドメイン | `auth.zombietyping.jp` |
| 送信者 | ゾンビタイピング |
| 送信元 | `login@auth.zombietyping.jp` |
| SMTPホスト | `smtp.resend.com` |
| ポート | `465` |
| ユーザー名 | `resend` |
| パスワード | 本人が作成したResendキーをSupabaseへ直接入力。Git・チャット・フロントへ保存しない |

Resendで表示されるDNSレコードを確認してからCloudflareへ追加する。値を推測しない。既存iOSアプリのドメイン・メール・認証キーを変更しない。本人の確認が必要な新しい権限・規約・認証情報の作成/入力は、準備した画面で本人へ引き継ぐ。

## 帰宅後から公開まで

1. 本人がChromeのResend登録画面から無料アカウントを作成する。Googleでの登録でも可。有料プランを選ばない。
2. 専用送信サブドメインの設定を準備し、必要なDNSレコード・権限を具体的に確認してから反映する。
3. 本人が送信用キーを作成してSupabaseのSMTP欄へ入力する。キーをチャットへ送らない。
4. 上記の短い日本語メールを設定する。メールの確認は必須のままにする。
5. 本人が指定したテスト先で、実メールが届くこと・番号による登録/ログイン・誤った番号/期限切れの拒否・同一Googleメールでの既存アカウントの扱いを確認する。無関係なアドレスへ送らない。サーバー側の送信制限も確認する。
6. 実配信確認後だけGitHub変数 `VITE_EMAIL_AUTH_ENABLED=true` を設定して公開する。設定をfalseへ戻すとメール入口を停止でき、Googleログインと既存記録は維持される。

公式資料: [SMTP設定](https://resend.com/docs/send-with-supabase-smtp)、[料金](https://resend.com/pricing)、[Supabaseの標準送信の制限](https://supabase.com/docs/guides/auth/auth-smtp)。確認時点のFreeは月3,000通・1日100通。公開前に画面の条件を再確認する。
